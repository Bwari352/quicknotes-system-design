
# QuickNotes API Design

## 1. Overview

The QuickNotes API allows users to create, view, update and delete their notes. The backend team will build a REST API that communicates using JSON over HTTP.

## 2. Base URL

```text
https://api.quicknotes.example.com/v1
```

This is a proposed URL for the API, not a live service.

## 3. Data Format

Requests and responses use JSON.

For requests containing a JSON body, the client must send:

```http
Content-Type: application/json
```

## 4. Endpoint Table

| Method | Endpoint | Purpose | Success Status |
|---|---|---|---|
| GET | /notes | Retrieve the user's notes | 200 OK |
| GET | /notes/{id} | Retrieve one note | 200 OK |
| POST | /notes | Create a new note | 201 Created |
| PUT | /notes/{id} | Update an existing note | 200 OK |
| DELETE | /notes/{id} | Delete a note | 204 No Content |

All endpoints require an authenticated user. The backend must ensure users can access and modify only their own notes.

## 5. Request and Response Examples

### 5.1 Retrieve All Notes

**Request**

```http
GET /v1/notes HTTP/1.1
Authorization: Bearer <access_token>
Accept: application/json
```

**Response — 200 OK**

```json
{
  "data": [
    {
      "id": 1,
      "title": "Study notes",
      "body": "Revise JavaScript and REST APIs",
      "category": "Study",
      "createdAt": "2026-10-21T10:00:00Z",
      "updatedAt": "2026-10-21T10:00:00Z"
    }
  ]
}
```

### 5.2 Retrieve One Note

**Request**

```http
GET /v1/notes/1 HTTP/1.1
Authorization: Bearer <access_token>
```

**Response — 200 OK**

```json
{
  "data": {
    "id": 1,
    "title": "Study notes",
    "body": "Revise JavaScript and REST APIs",
    "category": "Study",
    "createdAt": "2026-10-21T10:00:00Z",
    "updatedAt": "2026-10-21T10:00:00Z"
  }
}
```

### 5.3 Create a Note

**Request**

```http
POST /v1/notes HTTP/1.1
Authorization: Bearer <access_token>
Content-Type: application/json
```

**Request body**

```json
{
  "title": "Network security",
  "body": "Review network management controls",
  "category": "Study"
}
```

**Response — 201 Created**

```json
{
  "data": {
    "id": 2,
    "title": "Network security",
    "body": "Review network management controls",
    "category": "Study",
    "createdAt": "2026-10-21T10:30:00Z",
    "updatedAt": "2026-10-21T10:30:00Z"
  }
}
```

The server generates the note ID and timestamps.

### 5.4 Update a Note

**Request**

```http
PUT /v1/notes/2 HTTP/1.1
Authorization: Bearer <access_token>
Content-Type: application/json
```

**Request body**

```json
{
  "title": "Updated network security",
  "body": "Review firewalls and access controls",
  "category": "Study"
}
```

**Response — 200 OK**

```json
{
  "data": {
    "id": 2,
    "title": "Updated network security",
    "body": "Review firewalls and access controls",
    "category": "Study",
    "createdAt": "2026-10-21T10:30:00Z",
    "updatedAt": "2026-10-21T11:00:00Z"
  }
}
```

The server updates the note's content and `updatedAt` timestamp.

### 5.5 Delete a Note

**Request**

```http
DELETE /v1/notes/2 HTTP/1.1
Authorization: Bearer <access_token>
```

**Response — 204 No Content**

The server successfully deletes the note and returns no response body.

## 6. Validation Rules

- `title` is required and must contain non-whitespace characters.
- `title` must not exceed 100 characters.
- `body` is optional and must be a string when provided.
- `category` must be one of `Personal`, `Work`, or `Study`.
- The server validates all incoming data, even if the client already validates it.
- Note IDs are generated by the server and cannot be supplied to create a note.

## 7. Error Codes and Responses

| HTTP Status | Error Code | Meaning |
|---|---|---|
| 400 | VALIDATION_ERROR | The request contains invalid data |
| 401 | UNAUTHENTICATED | Authentication is missing or invalid |
| 403 | FORBIDDEN | The user is not permitted to perform the operation |
| 404 | NOTE_NOT_FOUND | The requested note does not exist or is inaccessible |
| 409 | CONFLICT | The request conflicts with the current resource state |
| 413 | PAYLOAD_TOO_LARGE | The request body exceeds the permitted size |
| 415 | UNSUPPORTED_MEDIA_TYPE | The request uses an unsupported content type |
| 429 | RATE_LIMITED | Too many requests were sent |
| 500 | INTERNAL_SERVER_ERROR | An unexpected server error occurred |
| 503 | SERVICE_UNAVAILABLE | The service is temporarily unavailable |

### Example Error Response

**Response — 400 Bad Request**

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The request contains invalid data.",
    "details": {
      "title": "Title is required and must not exceed 100 characters."
    }
  }
}
```

Error responses must use a consistent JSON structure and must not expose passwords, tokens, stack traces, or other sensitive server details.

## 8. Security Requirements

- Require authentication for all note endpoints.
- Authorize every operation against the authenticated user's notes.
- Validate and sanitize incoming data on the server.
- Use HTTPS in production.
- Apply rate limiting to protect the API from abuse.
- Never expose sensitive information in error responses.

## 9. Design Assumptions

This document defines the proposed API contract for the QuickNotes backend. The example domain is illustrative and is not a deployed service. Authentication, database persistence, and endpoint implementation will be provided by the backend team.
